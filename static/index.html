🧩 专家模式 (自定义 URL 音源)

通过语音口令触发你自定义的 HTTP 接口/直链音频，插件会自动解析返回结果并推送播放。URL 中可用 {keyword} 占位符注入语音里的关键词。

➕ 新增控制条目
🔌 纯指令调用：仅向 URL 发起一次请求（用于开关设备、触发 Webhook 等），不会播放任何音乐。
💡 此类条目无需后续关键词：喊完口令（如「打开灯」）即触发。若 URL 中不含 {keyword} 占位符，关键词同样可省略。

🧪 测试调用 (仅解析预览，不会推送到音箱)
🧠 问答接管 (AI 大脑)

说出「触发口令 + 你的问题」（例如「问问今天北京天气怎么样」），插件会先打断小爱自己的应答，再让大模型生成回答并朗读。 触发口令之后的词会原样交给模型，不会被动平台搜索词规则删改。

多个口令用逗号分隔。建议选不容易与歌曲搜索混淆的词。
🔌 大模型接口 (OpenAI 兼容)
切换预设会自动填入接口地址、模型名与扩展字段，之后只需再填 API Key。
仅保存在本机插件数据库中，不会外传。
点「获取模型」会从接口拉取可用模型列表，之后点输入框即可下拉选择。也可以直接手动输入。
用于透传各家私有参数。推理模型必须带 enable_thinking: false，否则会先吐思维链、延迟翻好几倍。
🎭 人设与长度控制
只描述性格与语气。口语化、字数上限、禁用格式符号等硬约束由插件内置强制，改写人设不会破坏它们。
实测大模型约 18~20 毫秒/字，400 字要等 7 秒以上。字数上限负责截断兜底，max_tokens 负责从源头限制 —— 两道闸只设一个都不保险。
🎯 接管时机
真机实测：连续下发 4 次停止指令，小爱的原生回答照样念完了。 设备侧的语音播报起播时机不可控，我们抢不过它 —— 硬抢就会变成「先说一遍小爱的、再说一遍模型的」。 所以默认改成只补位：小爱答得上来我们就闭嘴，只有它说「抱歉，暂不支持」这类话时才让大模型上。
原生回答命中其中任意一个，就判定为「小爱没答上来」，交给大模型。判定前会抹掉标点与空格， 所以「抱歉，目前暂不支持该功能」能命中「暂不支持」。清空表示永不接管。
小爱的回答通常与指令同一帧到达；万一慢一拍，最多再等这么久再判定。设 0 表示不等（到点没有就当它没答上来）。
开着之后，你直接跟小爱聊天、没喊「问问」，但它回了「对不起，我还在学习中」这类答不上来的话， 也会交给大模型补位。只在小爱明确答不上来时才接管 —— 正常指令（下一首、暂停、天气…） 小爱都有回答，不会被抢。默认关闭：没有口令词就没有归属边界，开着可能被无关对话触发。
判定为「需要接管」之后、模型返回之前，先跟用户打个招呼，避免他以为音箱没听见。 提示是和大模型请求并行的，不额外增加等待时间。 ⚠️ 开启后会自动改用单发打断 —— 连续打断窗口会把你自己刚播的提示语掐掉。
越短越好，1~2 秒念完最舒服。写太长会拖慢整体节奏（模型答得比它慢时才不会额外等待）。
答案要等提示语播完才下发，避免两者互相切断。模型耗时超过这个值时就以模型为准。
用当前词表判定，不调大模型、不下发到音箱。真机上听到小爱答了什么，直接粘进来试。
🔇 打断小爱原生应答
仅「全接管」模式下用得上（补位模式下小爱答上来了我们根本不出声，无需打断）。 你说「问问…」时，小爱会先把它自己的回答念出来，本插件随后打断、改念大模型的回答。 但设备什么时候起播我们看不到 —— 可能收到文字之前就开念了，也可能还要再等一两秒才起播。 只打一发停止指令，万一正好落在它起播前的空档上就会空转。 连续打断会在等待大模型期间反复下发停止指令，直到答案就绪才收手。 ⚠️ 真机上这一招目前没能压住小爱的播报，所以它只是个可开关的备选，不是默认路径。
仅「连续打断」时生效，指两发停止指令之间的真实间隔（单次下发本身的往返约 130 毫秒会被自动扣除）。 间隔越小越不容易漏掉起播，但下发越频繁。350 毫秒是个折中；改小到 200 附近更保险。

📖 插件简介

本插件是针对 SongLoft 智能音箱（MIoT）插件的功能增强补充工具。通过实时截获小爱音箱的语音指令，允许用户自由配置多样化的语音口令，自动联动 WebDAV 网盘、LXMusic 全网音源 等第三方音源插件，实现智能精准搜歌、匹配歌单并自动下发推送播放。

✨ 核心特性
  • 🎯 全局意图路由：自由定义唤醒词口令，灵活绑定至不同 WebDAV 节点或 LXMusic 平台策略。
  • 🧠 智能纠错重写：内置云端纠错算法，自动修正语音识别出的同音字、错别字，大幅提升命中率。
  • 🚀 自动化推流：听到口令后秒级完成匹配、自动创建推流歌单并呼叫小爱音箱开始播放。
  • 📡 全链路诊断：内置 WebSocket 对话实时截获与后端日志流，搜歌推流过程一目了然。
